### Проектирование Data Warehouse для фитнес-клуба

### 1. Описание бизнес-процесса и детализации (Grain)

* **Бизнес-область:** Управление фитнес-клубом.
* **Бизнес-процесс:** Продажа абонементов, клубных карт и дополнительных услуг (персональные тренировки, спа, аренда шкафчиков).
* **Уровень детализации (Grain):** Одна строка в таблице фактов соответствует факту одной транзакции продажи конкретной позиции (номенклатуры) определенному клиенту, совершенной сотрудником клуба в конкретный момент времени.

### 2. Архитектура данных

Для реализации выбрана схема **«Звезда» (Star Schema)**, так как она минимизирует количество соединений (JOIN) при выполнении аналитических запросов, проста в понимании и обеспечивает высокую скорость чтения. 

### Таблицы измерений (Dimension Tables)

1. **dim_clients** — демографические и профильные данные клиентов клуба.
2. **dim_products** — каталог продаваемых услуг, абонементов и тренировок.
3. **dim_staff** — информация о сотрудниках, оформивших продажу (менеджеры отделов продаж, тренеры).
4. **dim_date** — календарное измерение для построения временных отчетов и выявления сезонности.

### Таблица фактов (Fact Table)

* **fact_sales** — накапливает метрики транзакций (стоимость, количество, скидки) и содержит внешние ключи на все связанные таблицы измерений.

### 4. SQL-скрипт (DDL и аналитические запросы)

-- 1. Создание таблиц измерений.

CREATE TABLE dim_clients (
    client_key INT PRIMARY KEY,
    client_id INT NOT NULL,
    full_name VARCHAR(150) NOT NULL,
    gender VARCHAR(10),
    age_group VARCHAR(20)
);

CREATE TABLE dim_products (
    product_key INT PRIMARY KEY,
    product_id INT NOT NULL,
    product_name VARCHAR(100) NOT NULL,
    product_type VARCHAR(50),
    duration_days INT
);

CREATE TABLE dim_staff (
    staff_key INT PRIMARY KEY,
    staff_id INT NOT NULL,
    full_name VARCHAR(150) NOT NULL,
    position VARCHAR(50)
);

CREATE TABLE dim_date (
    date_key INT PRIMARY KEY,
    full_date DATE NOT NULL,
    year INT NOT NULL,
    quarter INT NOT NULL,
    month INT NOT NULL,
    day_of_week VARCHAR(15) NOT NULL
);

-- 2. Создание таблицы фактов.

CREATE TABLE fact_sales (
    sale_id INT PRIMARY KEY,
    date_key INT REFERENCES dim_date(date_key),
    client_key INT REFERENCES dim_clients(client_key),
    product_key INT REFERENCES dim_products(product_key),
    staff_key INT REFERENCES dim_staff(staff_key),
    quantity INT NOT NULL CHECK (quantity > 0),
    amount NUMERIC(10, 2) NOT NULL,
    discount_amount NUMERIC(10, 2) DEFAULT 0.00
);

-- 3. Аналитические запросы.

-- Запрос 1: Топ-3 самых прибыльных типов продуктов за текущий год.
-- На какой вопрос отвечает: Какие категории услуг (абонементы, доп. услуги, персональные тренировки) приносят клубу наибольший доход?
SELECT 
    p.product_type,
    SUM(f.amount) AS total_revenue,
    SUM(f.quantity) AS total_sold
FROM fact_sales f
JOIN dim_products p ON f.product_key = p.product_key
JOIN dim_date d ON f.date_key = d.date_key
WHERE d.year = 2026
GROUP BY p.product_type
ORDER BY total_revenue DESC
LIMIT 3;

-- Запрос 2: Эффективность работы персонала по продажам.
-- На какой вопрос отвечает: Кто из сотрудников генерирует наибольшую выручку и насколько агрессивно они используют скидки для закрытия сделок?
SELECT 
    s.full_name AS employee_name,
    s.position,
    SUM(f.amount) AS revenue_generated,
    SUM(f.discount_amount) AS total_discounts_given
FROM fact_sales f
JOIN dim_staff s ON f.staff_key = s.staff_key
GROUP BY s.full_name, s.position
ORDER BY revenue_generated DESC;

-- Запрос 3: Объем выручки по демографическим сегментам клиентов.
-- На какой вопрос отвечает: Какая группа клиентов (по возрасту и полу) наиболее финансово ценна для фитнес-клуба?
SELECT 
    c.age_group,
    c.gender,
    SUM(f.amount) AS revenue,
    COUNT(DISTINCT f.client_key) AS unique_buyers
FROM fact_sales f
JOIN dim_clients c ON f.client_key = c.client_key
GROUP BY c.age_group, c.gender
ORDER BY revenue DESC;

-- Запрос 4: Помесячная динамика выручки и среднего чека.
-- На какой вопрос отвечает: Как распределяется выручка клуба по месяцам года, наблюдаются ли сезонные спады и как меняется средний чек покупки?
SELECT 
    d.year,
    d.month,
    SUM(f.amount) AS monthly_revenue,
    AVG(f.amount) AS average_cheque
FROM fact_sales f
JOIN dim_date d ON f.date_key = d.date_key
GROUP BY d.year, d.month
ORDER BY d.year DESC, d.month DESC;
